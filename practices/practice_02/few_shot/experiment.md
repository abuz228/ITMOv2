# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: `problem.md`, раздел «Метрики».
- Что хотим улучшить: метрики M1/M2 не имеют числового текущего значения и правила подсчёта; цель «как поймём, что стало лучше» не проверить по сохранённым результатам.

## Примеры

### Хороший результат

```text
| M1: доля рисков со ссылкой на файл и место | P1-01: 11/11 = 100% (у каждой находки есть путь к файлу и строки) | 100% | Пересчёт по результатам запусков | results/P1-01.txt, results/P1-02.txt |
```

Правило подсчёта задано, базовое значение взято из реального файла результата, цель и источник проверки указаны.

### Плохой результат

```text
| M1: качество рисков | Плохо где-то | Станет лучше | Когда-нибудь | Журнал |
```

Нет текущего значения, нет правила подсчёта, цель не измерить, источник ссылки не указан.

## Запрос

```text
Ниже два примера описания продуктовой метрики: плохой и хороший.
Перепиши раздел «Метрики» в practices/practice_01/problem.md в стиле
хорошего примера: для каждой метрики M1 и M2 укажи правило подсчёта,
числовое текущее значение по результатам P1-01/P1-02 (results/*.txt),
целевое значение, момент замера и источник данных. Не добавляй метрики,
которых нет в текущем разделе. Не выдумывай числа и пороги.
```

## Что получили (исторический запуск на Big Pickle)

Отвечено в стиле хорошего примера (первая попытка на Big Pickle; использовалась для ориентира, но не для сравнения техник):

- Правило подсчёта M1: находка считается учтённой, если содержит путь к файлу и конкретное место (строки или функцию).
- Правило подсчёта M2: риск подтверждён, если обоснование выводится из содержимого diff; для этого нужны сведения вне diff — не подтверждён.
- M1 по P1-01: 11/11 = 100% (все находки содержат `app/...` и строки). M1 по P1-02: 3/3 = 100%.
- M2 по P1-01: 7/11 = 64% (подтверждённые: находки 1, 2, 4, 6, 7, 9, 11; неподтверждённые: 3 — `dependencies.py` вне diff, 5 — версия Python, 8 — продуктовое намерение, 10 — требования auth/rate-limit).
- M2 по P1-02: 2/3 (риски KeyError и prompt-injection по цитатам из diff; третий «блокирующий вызов» — видимое отсутствие асинхронности, но деградация под нагрузкой не доказана diff) ≈ 67%.
- Цели: M1 — 100%; M2 — 100% выданных рисков, остальные помечаются `possible` (по Master Prompt v1.1).

## Что получили (повтор на VseLLM / openai/gpt-5 — основной)

Повторили запрос на текущей модели. Результаты аналогичны по структуре, но численные выводы по M2 использовать нельзя без оценки студента. Значение M2 = 7/11, предложенное моделью, студентом отклонено и не является итоговым изменением артефакта.

## Что изменили в исходном артефакте

- Файл и раздел: `problem.md`, раздел «Метрики»; добавлено правило подсчёта и уточнены значения.
- Изменение: обновлена таблица метрик (файл и место; подтверждённость diff): M1 измерено по P1-01 (и пересчитывается по P1-02), для M2 — фиксируется по оценке студента (без авто‑пересчёта); добавлена строка в «Как использовали AI» со ссылкой на этот эксперимент.
- Как проверили: пересчитали M1 по содержимому `results/P1-01.txt` (11 находок) и `results/P1-02.txt` (3 риска) вручную; `make step2` проходит. M2 численно не фиксировали без оценки студента.
- Что отклонили: предложение добавить метрику M3 «время ответа» с числовым порогом — порог не задан в контексте; числовое значение M2 = 7/11 (64%) — предложено моделью, но отклонено студентом и не является итоговым изменением `problem.md`.

## Примечание о моделях

- Первоначальный запуск Few-shot выполнялся на другой модели (Big Pickle) из-за технической проблемы. Он сохранён в этом файле как контекст, но не используется для сравнения шести техник.
- Текущий повтор выполнен на модели VseLLM / openai/gpt-5 и является основным для сравнения техник.

## Оценка студента (повтор на VseLLM / openai/gpt-5)

- Принято: структура раздела «Метрики», правила подсчёта M1/M2, источники данных и момент измерения; M1 = 11/11 для P1-01 выглядит корректно.
- Не принято: конкретное значение M2 = 7/11 для P1-01. Причина: для M2 необходимо опираться на оценку студента по P1-01, а не переоценивать подтверждённость автоматически. Классификацию замечаний согласуем отдельно. Это значение не применяется в `problem.md`.
- Статус изменений файлов: practices/practice_01/problem.md не изменён в части baseline M2 в рамках этого повтора.
