# RAG

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: `practices/practice_01/problem.md`, раздел «Метрики`.
- Модель: VseLLM / openai/gpt-5.
- Разрешённые источники: `practices/practice_01/context.md`, `practices/practice_01/problem.md`, `practices/practice_01/prompts.md`, `practices/practice_01/results/P1-01.txt`, `practices/practice_01/results/P1-02.txt`.

## Запрос (RAG)

Проверь и улучши раздел «Метрики» так, чтобы каждое фактическое утверждение о M1, M2, baseline и результате после улучшения было связано с одним из разрешённых источников. Действуй по шагам:
1) Выпиши факты из разрешённых источников, относящиеся к M1 и M2, с указанием источника.
2) Проверь текущий раздел «Метрики» в `problem.md`. Для каждого значения или правила отметь: подтверждается источником / не подтверждается / требует оценки студента.
3) Предложи исправленную версию раздела «Метрики», если необходимо. Не придумывай отсутствующие значения. Если M2 нельзя получить только из файлов результатов без оценки студента — явно укажи это.

## Факты из источников (по теме M1/M2)

1) context.md
- Делать выводы только на основании diff; проверки должны быть воспроизводимыми (Context Pack: факты и правила).

2) prompts.md (Practice 1)
- P1-01 и P1-02 — сохранённые результаты запусков; P1-02 содержит до 3 рисков с файлами/доказательствами; введено различие confirmed|possible в v1.1; проверки должны проверять текущее поведение.

3) results/P1-01.txt
- 11 находок с ссылками на файлы/строки; есть как подтверждённые diff риски (KeyError), так и предположения, требующие контекста (версия Python, auth/rate limit и т.п.).

4) results/P1-02.txt
- 3 риска: KeyError по `payload["diff"]`; prompt injection/DoS; синхронный вызов LLM (возможна деградация). Первые два подкреплены цитатами из diff, третий требует контекста/нагрузочного сценария.

5) problem.md (текущая версия)
- Правила подсчёта: M1 — наличие файла и места; M2 — подтверждение строго по diff; `possible` не считать как `confirmed`.
- Таблица (вариант C): отдельные колонки Baseline (P1-01) и После улучшения (P1-02). M1 baseline: 11/11 = 100% (по results/P1-01.txt). M2 baseline: «по оценке студента P1-01 (не пересчитывать автоматически)». После улучшения: пересчёт по P1-02 (для M1) и «по оценке студента P1-02» (для M2). Цель M2: confirmed — только по diff; при недостатке данных — possible и не учитывается как confirmed.

## Проверка текущего раздела «Метрики»

- Правило M1 (файл+место, ручной подсчёт): подтверждается context.md (воспроизводимость) и соответствует prompts.md; непротиворечиво с P1-01/P1-02.
- Правило M2 (подтверждение только по diff, possible не считается confirmed): подтверждается prompts.md (v1.1) и соответствует контексту; непротиворечиво с P1-02 (третий риск возможный).
- M1 Baseline 11/11 (по results/P1-01.txt): подтверждается источником P1-01.txt (11 находок с файлами/строками).
- M1 После улучшения «пересчёт по results/P1-02.txt»: корректно сформулировано как операция, без выдуманных чисел; подтверждается наличием файла P1-02.txt.
- M2 Baseline «по оценке студента P1-01 (не пересчитывать автоматически)»: требует оценки студента (по условиям); корректно отмечено как неавтоматический расчёт; не противоречит источникам.
- M2 После улучшения «по оценке студента P1-02 (не пересчитывать автоматически)»: требует оценки студента; корректно отмечено как неавтоматический расчёт; не противоречит источникам.
- Цель M2 «confirmed только при доказательствах в diff; possible явно не учитывается»: подтверждается prompts.md и context.md.

Вывод: раздел «Метрики» уже соответствует разрешённым источникам. Единственное усиление — явно указать в таблице для M1 после улучшения, что значение берётся из `results/P1-02.txt` пересчётом по тому же правилу, и сохранить примечание о хранении файлов (уже есть).

## Предлагаемая правка (минимальная, при необходимости)

Текущая формулировка раздела «Метрики» удовлетворяет требованиям RAG. Изменения не требуются. Допустимое уточнение (необязательное): оставить текущую формулировку «Пересчёт по `results/P1-02.txt`», так как она уже присутствует и не вводит новых чисел.
