# Style Guide — проект demo

Короткий набор правил разработки для нашего небольшого Python-сервиса
подписчиков (`service.py`). Источник требований — `docs/requirements.md`
(контракт); при любом расхождении контракт главнее этого файла. Правила
применяются к Feature A, Feature B и к любым правкам сервиса и тестов.

## Правила

### 1. Проверяй поведение через публичный интерфейс, используя unittest

Тесты вызывают публичные функции модуля (`subscribe`, `unsubscribe`) и
наблюдают результат: возвращаемое значение и состояние `subscribers`. Не
тестируй приватные детали и не дублируй реализацию — проверяй поведение,
описанное в контракте.

### 2. Сохраняй существующие соглашения об именовании и обработке ошибок

- Функции и переменные — `snake_case`; тесты — `test_<функция>_<сценарий>`.
- Имя подписчика нормализуется через `strip()`.
- Пустое имя (или имя, пустое после нормализации) — всегда
  `ValueError("empty name")` с тем же текстом сообщения.
- Новая функция повторяет уже принятый шаблон, а не вводит свой.

### 3. Не добавляй внешние зависимости и сложные абстракции ради маленькой функциональности

Задача решается средствами стандартной библиотеки и уже существующего кода.
Новые пакеты, фреймворки, слои и обобщения не добавляются без реальной
необходимости.

### 4. Не изменяй контракт и не ослабляй тесты ради успешного результата

Поведение берётся из `docs/requirements.md` и не подгоняется под код. Нельзя
удалять тесты, ослаблять проверки или менять ожидания, чтобы получить
зелёный результат; сначала исправляется реализация. Runner не ослабляется.

### 5. Запускай единый runner после изменений

После любой правки реализации или тестов из корня проекта выполняется
`./scripts/check.sh`. Все тесты должны проходить; красный результат честно
сообщается, а не скрывается.

## Хороший пример из Feature A — `unsubscribe`

Реализация `service.py`:

```python
def unsubscribe(name):
    normalized = name.strip()
    if not normalized:
        raise ValueError("empty name")
    if normalized in subscribers:
        subscribers.remove(normalized)
        return True
    return False
```

Тест `tests/test_service.py`:

```python
def test_unsubscribe_missing_returns_false_and_keeps_state(self):
    subscribe("alice")

    result = service.unsubscribe("bob")

    self.assertIs(result, False)
    self.assertEqual(subscribers, {"alice"})
```

Какие правила демонстрирует пример:

- **Правило 1** — тест работает через публичный интерфейс (`service.unsubscribe`)
  и проверяет результат и состояние `subscribers`, а не внутренности.
- **Правило 2** — `unsubscribe` повторяет соглашения `subscribe`:
  `strip()` и `ValueError("empty name")`; тест назван по шаблону
  `test_unsubscribe_<сценарий>`.
- **Правило 3** — реализация использует только встроенные `set`/`str`, без
  зависимостей и лишних абстракций.
- **Правило 4** — тест фиксирует поведение из контракта (нет подписчика →
  `False`, состояние не меняется) и не ослаблен ради зелёного результата.
- **Правило 5** — пример проверяется тем же runner: `./scripts/check.sh`.

## Связь с AGENTS.md

`AGENTS.md` требует прочитать этот файл перед изменением кода. Это сделано
явной ссылкой намеренно: в OpenCode 2.0.20 поле `instructions` не загружает
файл автоматически, поэтому файл читается по явному требованию.
