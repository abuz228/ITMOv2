# AGENTS.md — правила работы над проектом demo

## 1. Назначение проекта

Небольшой учебный Python-сервис для управления подписчиками (subscribers).
Проект используется в Practice 4: на нём настраивается среда агента и
реализуются две небольшие фичи.

## 2. Расположение файлов

- Контракт (источник требований): `docs/requirements.md`
- Реализация: `service.py`
- Пример тестов: `tests/test_service.py`
- Единый runner: `scripts/check.sh`

## 3. Проверка

- Из корня проекта demo: `./scripts/check.sh`
- Проверка использует `unittest`.
- После изменения реализации или тестов необходимо запускать runner и
  убеждаться, что все тесты проходят.

## 4. Правила работы

- Сначала читать контракт (`docs/requirements.md`) и существующие тесты.
- Не менять контракт и runner без отдельного разрешения.
- Не изменять существующее поведение `subscribe`.
- При разработке фич сначала добавлять тесты, затем реализацию.
- Не добавлять внешние зависимости без необходимости.
- Не скрывать ошибки тестирования и не ослаблять проверки.
- Изменять только файлы, необходимые для поставленной задачи.

## 5. Будущие задачи

- **Feature A**: `unsubscribe(name)`.
- **Feature B**: `is_subscribed(name)`.
- Обе фичи должны строго соответствовать `docs/requirements.md`.
