## Context Pack для первого рабочего сценария

### Факты и правила

- На входе один diff; решение принимает человек; AI не может approve/merge и не меняет код.
- Для одного PR помощник возвращает: краткое описание изменения, до 3 рисков, у каждого риска — файл/строка и доказательство, и список проверок.
- Проверки должны быть воспроизводимыми.

### Формат входа и результата

- Вход: текстовый git diff (например, TRAINING_PR.diff).
- Результат: Summary (краткое описание), Risks (<=3, со ссылками и доказательствами), Checks (список проверок).

### Ограничения и запрещённые действия

- Делать выводы только на основании diff.
- Запрещено approve/merge, менять код, использовать внешние источники без ссылки.

### Хороший пример

app/api.py, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews
с пустым JSON-объектом и проверить ответ сервиса.
### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.
### Что пока неизвестно

- Целевая версия Python для проекта.
- Ограничения на размер diff (если есть).
- Конкретный Git-провайдер и наличие CI для этого сценария не указаны.
